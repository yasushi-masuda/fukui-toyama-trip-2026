# リモート可視性ルール

> Owner がリモートからでもリアルタイムで状況を追えるようにするためのルール

---

## 原則

**Tick ごとに台帳を更新し、git push する。Owner は GitHub を見るだけで最新状況を把握できる。**

---

## タスク状態変更時の必須アクション（随時実行 — Tick 完了を待たない）

> **重要: Tick の最後にまとめて更新するのではなく、タスクの開始・完了・課題発生のたびに即座に更新 + push する。**

### 1. WBS 更新（作業ごと、検証込み）

タスクを完了にする際、単に「実施済み」にするのではなく、**正しく実行されたかの検証結果も記録する**。

```yaml
# TASKS.yaml の更新例
- id: T-IL-010
  status: done
  completed: "2026-04-01"
  verification: "Azure Portal で URI が表示されることを確認済み"  # ← 必須
```

WBS ファイル（`outputs/2026-03-28/WBS_BDX-PoC_招待不要アーキテクチャ.md`）のタスク表も同時に更新する:
- 状態列を「⏳ 未着手」→「🔄 作業中」→「✅ 完了」に変更
- 検証結果列に「何を確認して OK だったか」を簡潔に記入
- 備考列に「何をやったか」を簡潔に記入（上司やクライアントが見て分かる粒度）
- 問題があった場合は「⚠️ 要確認: [内容]」を付記
- **WBS は OrgOS を知らない上司やクライアントも見る。プレビューだけで進捗が分かるように書く。**

### 2. 課題管理表への即時起票

課題が発生したら、どんなに小さくても `.ai/ISSUES.md` に即時起票する。

```markdown
| ISS-001 | 2026-04-01 | P2 | 認証 | access_as_user スコープ追加時に Azure Portal でエラー | T-IL-011 | OPEN | 横谷 | | |
```

- DASHBOARD.md のブロッカー欄にも P0/P1 は即反映
- 解決したら解決策と日付を記入
- 設計書と実動作が異なった場合は、設計書の修正タスクも起票する

### 3. git push（タスク状態変更のたびに即時実行）

タスクの開始・完了・課題発生のたびに、**即座に git commit + push する**。Tick の最後にまとめてではなく随時実行。

```bash
git add .ai/ outputs/
git commit -m "progress: [イベント概要]"
git push
```

コミットメッセージの例:
- `progress: T-IL-010 開始（Application ID URI 設定）`
- `progress: T-IL-010 完了（Portal で URI 確認済み）`
- `progress: ISS-001 起票（access_as_user スコープ追加でエラー）`
- `progress: ISS-001 解決（スコープ名のタイプミスを修正）`

---

## STATUS.md の更新フォーマット

毎 Tick、STATUS.md に以下の形式で 1 エントリ追加する:

```markdown
### Tick #N (YYYY-MM-DD HH:MM)

**完了**: T-IL-XXX [タスク名]
**検証**: [何を確認して OK だったか]
**課題**: なし / ISS-XXX を起票（[概要]）
**次**: T-IL-YYY [次のタスク名]
**ブロッカー**: なし / [ブロッカーの内容]
```

---

## DASHBOARD.md のブロッカー欄

ブロッカーが発生した場合、DASHBOARD.md の `⚠️ Blockers` セクションに即反映:

```markdown
## ⚠️ Blockers

| ID | 発生日 | 内容 | 影響タスク | 対応状況 |
|----|--------|------|-----------|---------|
| ISS-001 | 2026-04-01 | access_as_user スコープ追加時にエラー | T-IL-011 | 調査中 |
```

ブロッカーが解消されたら行を削除し、`(なし)` に戻す。

---

## チェックリスト（タスク状態変更のたびに確認）

- [ ] TASKS.yaml: status を更新したか
- [ ] WBS: 該当タスクの状態・検証結果・備考・完了日を更新したか
- [ ] ISSUES.md: 課題があれば起票したか
- [ ] DASHBOARD.md: ブロッカー欄を更新したか（P0/P1 の場合）
- [ ] git commit + push したか

**1つのタスクが完了するたびにこのチェックリストを実行する。まとめて後回しにしない。**
