# /org-wbs — WBS 確認・調整コマンド

`wbs-operations` スキルを使って、マスター WBS（TMC共有用Excel）を確認・調整する明示起動コマンド。

## 引数

`$ARGUMENTS` で動作を切り替える:

| 入力 | 動作 |
|------|------|
| （なし） | **進行中のWBS作業があれば、そこから継続**（下記「Step 0」）。無ければ今週＋今日を表示 |
| `today` | 今日のタスクだけ |
| `week` | 今週のタスク |
| `load <名前>` | その担当の週次工数（超過つき） |
| `themes` | テーマ別工数合計 |
| `<名前>` 単独 | その担当で今週＋今日 |
| `report` | 継続をスキップして、今週＋今日のレポートだけ出す |

## Step 0：進行中のWBS作業の継続（引数なしのとき最初に実行）

**`.ai/TASKS.yaml` の `T-TL-WBS-*` を確認する。** `queued` / `running` があれば、**レポートより先にそこから継続する**。

1. 該当タスクの `notes` を読む（**次にやること・現在の数値・注意点が全て書いてある**）
2. notes が指す md を**その順番どおりに**開く
3. Owner に「ここから再開します」と現在地を示してから着手する
4. 完了したら該当タスクを `done` にして、次タスクを起票する

> **現在の進行中タスク（2026-07-21 時点）**: `T-TL-WBS-002`（status: running）
> **次にやること**: **テーマごと・工程の手前から Lv4 認識合わせ**（テーマA→B→C の順）
> **SSOT**: `outputs/2026年7-8月取組み/00_共通/作業計画/作業計画_統合WBS一覧.md`
> 　└ 📖背景 → 📊サマリ（認識合わせの進捗）→ 各テーマの工程表 の順に読む
> 　└ **旧ファイル（`作業計画_タスク一覧_Lv4_完了要件つき.md` ／ CSV ／ gen スクリプト）は `作業計画/old/` に退避済。参照しない**
> **マスターWBS（Excel）とは同期しない**（2026-07-21 Owner 指示）。統合WBS一覧を直接編集する
> **進め方**: 工程ごとに「いま書いているもの」＋「Manager の欠陥仮説」をセットで出し、対話で確定する

## ⚠️ レーン分離：設計書を読まない

**このコマンドで動くWBSレーンは、設計書（`20_設計/概要設計書_招待レス方式.md`）を読まない。**

理由：**Owner が設計書を並行で編集している**ため、読むと**編集途中の状態を掴んで誤った判断をする**（2026-07-16 に実際に発生：編集前の §4 を読んで「フローチャートと処理内容一覧が重複」と誤指摘 → Owner が構成変更中だったため撤回）。

- 設計書の**実態・進捗・構成は Owner が持っている**。**工数や粒度は Owner に聞く**こと
- 設計書の内容を根拠に使いたくなったら、**読まずに Owner に確認する**
- 例外：Owner が「この節を見て」と明示したときのみ

## 実行手順

1. **`wbs-operations` スキルを参照**（場所・列構成・鉄則を踏まえる）。
2. **読み取りツールを実行**（`Today's date` を基準にする。推測しない）:
   ```bash
   # 既定（今週＋今日, 湯田）
   python tools/wbs/wbs_report.py --week --who 湯田 --date <today>
   python tools/wbs/wbs_report.py --today --who 湯田 --date <today>
   ```
   `$ARGUMENTS` に応じて `--today` / `--week` / `--load --who <名前>` / `--themes` / `--who <名前>` を切り替える。
3. **結果を提示**：今週の予定・今日のタスク・（必要なら）週次工数の超過。
4. **調整を促す**：変更指示があれば、`wbs-operations` の書き込み手順
   （ロック確認 → バックアップ → COM編集 → 検証 → Refresh All案内）で反映する。
   段取りを組むときは [.agents/rules/knowledge/wbs/project-roster.md](../skills/wbs/project-roster.md) の合意フロー
   （作成 → 内部レビュー(小川) → 小林さん討議/最終合意）に従う。

## 注意

- 書き込みは Excel COM のみ（openpyxl 保存禁止）。クライアントマスターへの書き込みは実行前に Owner 確認。
- 完了後は必ず「データ → すべて更新」を案内（ピボット手動更新）。

## 次のステップ案内

実行後は必ず次を提示：
- 「Rxxx を◯日後ろに」等の調整 → その場で反映
- 継続作業が残っていれば **`/org-wbs` で続きから**（Step 0 が拾う）
- `/org-tick` で OrgOS 通常フローに戻る
